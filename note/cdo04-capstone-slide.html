04

Prediction Workflow

EventBridge Scheduler → SQS → Prediction Worker → AI Engine — mỗi 5 phút cho 3 service

04 · Worker

Prediction Worker Pipeline

SQS Receive→ Parse Job→ Query AMP 120'→ Align 1-min Buckets→ Gap Ratio Check→ AI Engine / Fallback→ Audit DynamoDB→ SNS Alert→ Delete SQS
Data Alignment
7 PromQL query_range calls, step=60s, start=end-120m. Forward-fill cho hầu hết signals, zero-fill cho queue_depth. Tính gap_ratio — nếu ≥ 0.5 thì fallback.
Message Safety
Worker chỉ delete SQS message sau khi audit write thành công. Nếu lỗi, message retry hoặc vào DLQ (maxReceiveCount: 5).

04 · AI Engine

AI Engine — STL + EWMA Detection

🏗
Architecture
ECS Fargate, private subnet, port 8080. Min 2 / Max 4 tasks. Rate limit 600 req/min/tenant.
📡
Call Path (Path A)
Worker → NAT → API Gateway AWS_IAM → VPC Link → internal ALB :80 → AI Engine :8080
🧠
Detection
Về detection logic, AI Engine dùng STL seasonal baseline kết hợp EWMA control chart. Nếu confidence thấp hơn 0.7, recommendation sẽ bị downgrade thành INVESTIGATE
AI Response Output
anomaly · severity · reasoning · recommendation (action_verb, target, from_to, confidence) · audit_id. Timeout hard limit: 2 giây — sau đó fallback.

05 · Fallback

AI Engine vs Static Threshold Fallback

AI Engine Path
Detection Method
STL baseline + EWMA control chart. Confidence-gated recommendations.
Output
anomaly, severity, reasoning, recommendation với action_verb cụ thể
Audit Source
prediction_source = AI_ENGINE
evidence_status = complete_window
Static Fallback Path
Trigger Conditions
AMP thiếu data · gap_ratio ≥ 0.5 · AI timeout · AI 5xx · AI 429 · Response sai schema
Output
Static threshold check theo service policy trong DynamoDB
Audit Source
prediction_source = static_threshold_fallback
fallback_reason = lý do cụ thể
Fail-open design
Fallback là cơ chế fail-open — hệ thống không im lặng khi AI lỗi. SRE biết rõ decision đến từ AI hay fallback qua audit record.

08 · Caveats

Documented Caveats

Nhóm không claim production-ready tuyệt đối

1
k6 3h — Operational Pass
27 dropped iterations và 19 failed requests trên 539,974 requests. Chấp nhận là operational pass (~0.0035% lỗi, ~0.005% drop) nhưng không phải strict zero-drop.
2
SigV4 Enforcement
SigV4 enforce ở API Gateway AWS_IAM. App-level SigV4 verification trong AI Engine là production hardening, chưa implement.
3
100 RPS Acceptance
Chưa được rerun trong final evidence pack. Nếu mentor yêu cầu, cần chạy lại 100 RPS 10 phút.
4
Cost Explorer Lag
Cost Explorer actuals có độ trễ. Cost được chứng minh bằng budget/cost-breaker + sizing model, không phải real-time Cost Explorer.
